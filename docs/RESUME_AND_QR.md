# 简历项目描述与二维码方案

## 1. 推荐的项目名称

不要只写“论文助手 Demo”。建议写：

> 论文记忆与引用助手｜面向研究生写作场景的 0→1 个人项目

角色可以写：

> 独立产品经理 / 原型搭建

## 2. PRD、流程图和 Demo 应该怎么放

它们不是简历里三个并列栏目，而是项目的不同证据：

| 项目环节 | 对应产物 | 简历表达 |
| --- | --- | --- |
| 发现问题 | 用户访谈、痛点归纳、竞品分析 | 发现了什么、影响谁、为什么值得做 |
| 设计方案 | PRD、用户流程、需求优先级 | 定义了什么 MVP、砍掉了什么 |
| 原型搭建 | 可交互 Demo、数据模型、错误处理 | 独立完成交互原型和核心闭环 |
| 验证迭代 | 测试记录、指标、版本变更 | 用什么结果推动下一次迭代 |

因此：

- PRD 主要支持“方案设计”。
- 用户流程是 PRD 的核心组成部分，也可以放在方案设计里。
- Demo 支持“原型搭建与验证”。
- 不要只写“输出 PRD”，要写 PRD 带来的关键决策。

## 3. 简历中的项目介绍模板

> **论文记忆与引用助手｜独立产品经理 / 原型搭建｜2026.08–至今**
>
> - **问题发现**：访谈 `__` 名论文写作者，发现“读过但找不到出处”、笔记割裂和引用核验耗时是高频痛点；将目标定义为帮助用户找回可追溯证据，而不是生成不可核对的答案。
> - **方案设计**：完成 PRD、用户流程和 P0/P1 优先级，定义导入、笔记、全文查证、证据问答和在线检索五大模块；设置 Top-3 命中率、可追溯率和无依据错误回答率作为核心指标。
> - **原型搭建**：独立搭建本地优先 Web Demo，支持 PDF 全文提取、IndexedDB 存储、中英文术语扩展、OpenAlex / Crossref 检索和开放 PDF 导入；覆盖无全文、接口限流和扫描版 PDF 等异常状态。
> - **验证迭代**：用 `__` 个真实问题和 `__` 名用户测试，核心任务成功率 `__%`，Top-3 命中率 `__%`，找证据耗时从 `__` 分钟降至 `__` 秒；根据测试将产品从“本地检索”迭代为“本地证据 + 在线发现 + 单篇全文查证”。

## 5. 二维码怎么放

### 推荐方案：一个二维码

二维码指向一个“项目案例页”，而不是直接指向 PRD 或 Demo。

项目案例页包含：

1. 30–90 秒 Demo 视频
2. 可交互 Demo 链接
3. PRD
4. 用户流程图
5. 关键产品决策
6. 验证结果和迭代记录

简历上写：

```text
[项目案例 / Demo / PRD]  imyour.product/projects/paper-memory
```

二维码下方加一句：

> 扫码查看 Demo、PRD 与迭代记录

### 不推荐方案：两个二维码

“Demo 一个码、PRD 一个码”会占用一页简历的视觉空间，也要求面试官做两次选择。一个项目主页更容易形成完整叙事。

### 二维码制作要求

- 尺寸：约 18–22 mm × 18–22 mm。
- 使用纯黑 / 白高对比度，不加复杂渐变和背景图。
- 二维码旁必须保留可读链接，满足 ATS 和纸质简历需求。
- 扫码后首屏必须能立即看到 Demo 视频和三个按钮：体验 Demo、阅读 PRD、查看用户流程。
- 线上 Demo 要有录制视频备用，避免网络或 API 限流时无法演示。

## 6. 推荐部署方式

### 快速上线

优先选择 Vercel、Netlify 或 GitHub Pages 部署静态页面。

要求：

- 线上 Demo 不依赖本机 `127.0.0.1`。
- `.mjs` 文件能以 JavaScript MIME 类型访问。
- 手机上打开时，核心流程可以操作或至少有视频兜底。
- 数据默认保存在用户自己的浏览器 IndexedDB 中，并在页面说明。

### 项目主页

可以使用 Notion、飞书或一个简单静态页面，把资料按下面顺序组织：

1. 问题与用户
2. 产品方案
3. Demo 视频
4. 用户流程
5. PRD
6. 验证与迭代
7. 下一阶段规划

## 7. 面试时要准备的三句话

1. **为什么做**：论文阅读是积累，写作是检索；真正的断点在“读过的证据找不回来”。
2. **怎么取舍**：优先做证据可追溯和明确拒答，不优先做大而全的生成能力。
3. **迭代依据**：用户需要判断某篇论文是否包含某个信息，因此增加单篇全文查证，而不是继续增加泛化聊天功能。

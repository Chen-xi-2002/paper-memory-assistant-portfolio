# 验证与迭代计划

> 这份文档用于避免项目只停留在“功能展示”。项目经理岗位更关注你如何定义用户、验证假设、解释取舍并推动迭代。

## 1. 需要验证的三个核心假设

### 假设 A：论文记忆断层是高频痛点

验证问题：

- 你多久会遇到“记得读过但找不到哪一篇”的情况？
- 最近一次发生在写什么内容时？
- 你现在怎么解决？耗时多久？

通过标准：至少 5 名受访者中，4 名在过去一个月遇到过该问题。

### 假设 B：带来源的回答比普通聊天更能建立信任

验证问题：

- 你更在意回答速度，还是能回到原文核对？
- 什么信息会让你相信一条引用是可靠的？
- 只有摘要、没有全文时，你希望系统如何回答？

通过标准：多数用户愿意牺牲部分速度换取来源可追溯。

### 假设 C：单篇论文查证是高频核心场景

验证问题：

- 你是否需要判断“这篇论文里有没有提到某个观点”？
- 目前你如何查找？使用 Ctrl+F 是否足够？
- 哪些情况需要系统明确回答“有 / 没有”？

通过标准：至少 3 名用户在写作或综述场景中明确提出该需求。

## 2. 用户访谈样本

建议招募：

- 2 名语言学 / 语音学方向研究生
- 2 名社会科学方向研究生
- 1 名理工科论文写作者
- 1 名正在写开题报告或综述的学生

访谈提纲：

1. 最近一次写论文时，如何找到以前读过的资料？
2. 笔记最常记在哪里？为什么不回看？
3. 引用出错或找不到来源会带来什么后果？
4. 你用过哪些文献管理工具？最不满意什么？
5. 你愿意把论文 PDF 上传到网页吗？
6. 你需要“生成答案”，还是更需要“找回证据”？
7. 如果系统找不到证据，哪种反馈更可信？

## 3. 可用性测试任务

| 编号 | 任务 | 成功标准 |
| --- | --- | --- |
| T1 | 导入一篇 PDF | 能看到全文、摘要和字符数 |
| T2 | 添加一条读后笔记 | 刷新后笔记仍然存在并能被搜索 |
| T3 | 提问一个需要引用的问题 | 能找到至少一条可追溯依据 |
| T4 | 判断某篇论文是否包含指定信息 | 得到有 / 没有结论和原句 |
| T5 | 搜索库外论文并加入元数据 | 能区分全文、摘要和待补 PDF |
| T6 | 在线接口失败时继续使用 | 本地功能不中断，能看到替代入口 |

记录：

- 完成 / 失败
- 完成时间
- 卡住的步骤
- 用户提出的原话
- 是否信任回答以及原因

## 4. 检索基准

建立 20 个真实问题，每题标记：

- 正确论文集合
- 正确依据类型：全文 / 笔记 / 标注 / 摘要
- 正确答案应包含的关键信息
- 是否存在故意无法回答的问题

指标：

- Top-1 命中率
- Top-3 命中率
- 引用定位成功率
- 无依据时拒答率
- 用户确认答案正确的比例
